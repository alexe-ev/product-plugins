Баг подтверждён и локализован. Baseline в complete-inputs дал 117,752/group — в 6.4× больше ожидаемого. Причина: в REFERENCE.md нет явной формулы, модель применяет вариант с дополнительным ×2.
→ Решение: добавить формулу с явным предупреждением «не умножать на 2».
🔧 Исправление REFERENCE.md — добавлена явная формула
n_per_group = (z_α/2 + z_β)² × (p1×(1−p1) + p2×(1−p2)) / (p2 − p1)²

Стандартные z-значения:
• 95% confidence (two-sided): z_α/2 = 1.96
• 80% power: z_β = 0.84 → (1.96 + 0.84)² = 7.84
• 90% power: z_β = 1.28 → (1.96 + 1.28)² = 10.50

⚠️ НЕ умножать на 2. Формула уже учитывает обе группы.
Также добавлена формула для continuous-метрик: n = (z_α/2 + z_β)² × 2σ² / δ²

Ключевые выводы

🔍
Главная находка: ×2-баг в расчётах
Без явной формулы в REFERENCE.md оба конфига систематически удваивали размер выборки. Стандартная формула двухвыборочного z-теста уже учитывает обе группы через сумму дисперсий — дополнительное ×2 ошибочно. Баг был обнаружен через eval-тестирование и исправлен напрямую в REFERENCE.md.
✅
with_skill стабильно обгоняет на граничных случаях
После исправления формулы оба конфига одинаково справляются со стандартными кейсами. Разрыв +13pp проявляется именно там, где нужна аккуратность: SD-оговорка для continuous-метрик и корректный расчёт total-duration вместо per-group.
📋
missing-inputs: with_skill даёт более структурированный ответ
При неполных входных данных with_skill корректно оформляет labeled scenarios с явными условиями, не выдавая единственную «рекомендацию». Baseline в iter 2 давал unconditional duration в exec summary — нарушение принципа conditional framing.
⚠️
unsafe-traffic: with_skill уверенно блокирует некорректные данные
Когда eligible users ≠ total registered, with_skill явно предупреждает и отказывается считать duration по некорректной базе. Baseline в iter 1 принял 25k зарегистрированных как eligible-трафик без предупреждения.
⚙️
Итерация ассерций — необходимая часть процесса
Ассерции iter 1 для missing-inputs запрещали любые числа, но REFERENCE.md явно разрешает labeled scenario estimates. Строгость ассерций должна соответствовать задокументированному поведению скила, а не интуиции.
📐
Continuous-метрики требуют дополнительной оговорки
Для continuous-метрик (session duration, revenue) размер выборки критически зависит от предполагаемого SD. with_skill добавляет предупреждение, что если реальное SD отличается от допущения — результат изменится. Это существенно для правильного планирования эксперимента.

Рекомендации

1
Высокий приоритет
Расширить calc-only тесты на больше типов метрик
Iter 4 покрывает conversion и continuous (session duration). Стоит добавить revenue-per-user (right-skewed, требует трансформации), retention rate (binomial но с учётом cohort dilution) и multi-variant (3+ ветки). Текущие 3 кейса не полностью покрывают пространство параметров.
2
Высокий приоритет
Добавить regression test для ×2-бага
Исправление в REFERENCE.md работает, но нет автоматического теста который поймает регрессию если формулу случайно изменят. Рекомендуется добавить assertion с точными ожидаемыми значениями (например, для стандартного 95%/80% кейса — конкретные числа в пределах ±5%) в постоянный eval suite.
3
Средний приоритет
Протестировать missing-inputs с частичными данными (3+ вариантов)
Текущий missing-inputs кейс покрывает полное отсутствие нескольких параметров. Интереснее проверить граничные случаи: есть baseline, нет MDE; есть MDE, нет SD; нет traffic. Поведение скила может различаться в зависимости от того, какие именно параметры отсутствуют.
4
Средний приоритет
Добавить в REFERENCE.md явный пример расчёта с пошаговыми вычислениями
Формула добавлена, но сквозной пример «от входных данных до результата» был бы полезен. Числовой пример с промежуточными значениями снижает вероятность новых вариаций ×2-бага и упрощает debugging.
5
Низкий приоритет
Рассмотреть тест на «одностороннее vs двустороннее» разграничение
Текущие тесты используют two-sided тесты (z_α/2 = 1.96). Есть сценарии где one-sided обоснован (например, «мы хотим знать только если новое лучше»). with_skill может вести себя иначе при явном указании one-sided hypothesis — это непроверенная зона.

Скил estimate-sample-size работоспособен и добавляет реальную ценность. Главная находка тестирования — систематический ×2-баг в расчётах, обнаруженный через eval и исправленный напрямую в REFERENCE.md. После исправления оба конфига корректно считают стандартные кейсы.
