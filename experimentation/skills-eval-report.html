На стандартных кейсах — ничья. Разрыв появляется на adversarial: при pseudo-complete входных данных baseline молча генерирует «compliance theater» план с несуществующими метриками и числами. Структурные скилы — 0pp изолированно, ценность в chain

Три скила ниже показали 100% у обоих конфигов. Baseline хорошо обучен на этих conceptual-паттернах. Ценность скилов — в нормализации формата вывода и vocabulary для downstream handoff. Измерить её можно только в chain-тесте.

analyze-experiment-results
Structural  ·  2 итерации  ·  6 eval-кейсов  ·  6-section output format
STRUCTURAL
100% / 100% — tie на всех 6 кейсах, включая novelty decay, volume confound, borderline результаты. Ценность скила — 6-секционный output format + result vocabulary (Positive / Positive with caution / Negative / Neutral / Inconclusive). Следующий шаг: кейсы с неявными сигналами (Simpson's paradox без указания, вычисление p-value из сырых чисел) + assertions на структуру вывода.
validate-experiment-quality
Structural  ·  2 итерации  ·  от явных паттернов до implicit числовых аномалий
STRUCTURAL
Baseline справился с SRM в таблице, CUPED significance flip, Bonferroni для post-hoc сегментов без скила. Ценность: риск-словарь Fatal/Manageable/Unresolved + audit checklist. Потенциальный Gap не протестирован: полностью отсутствующие процедурные свидетельства при видимо чистом результате — baseline может написать «вероятно нормально» вместо явного перечисления.
recommend-post-test-decision
Structural  ·  2 итерации  ·  guardrail conflict, business pressure, sub-MDE кейсы
STRUCTURAL
Baseline устойчив даже к guardrail conflict (checkout +4.5pp, AOV −8.2%) и sub-MDE с дедлайн-давлением. Ценность: 5-польный decision memo format + conditional recommendation rules для стандартизации. Реальная ценность проявится в цепочке analyze → validate → recommend.

Рекомендации и следующие шаги

Приоритизированный backlog — что делать дальше, в каком порядке и зачем.

1
Chain-тест для структурных скилов
Сырые данные → analyze → validate → recommend vs baseline на тех же данных. Единственный способ измерить реальную ценность структурных скилов.
2
Missing evidence restraint в validate-quality
Единственный Gap не покрытый тестами — полностью отсутствующие процедурные данные при видимо чистом результате. Потенциально критичный для production-решений.
3
Расширить light-context кейсы для define-metrics
Это главная зона ценности (+67pp), но текущее покрытие — всего 2 кейса из 6. Нужно ещё 3–5 доменов для уверенности в результате.
4
Regression-тест на формулу estimate-sample-size
Защита от реверта ×2 бага: числовые ожидаемые значения ±5% в постоянном eval suite.
5
REFERENCE.md для design-experiment-plan
Добавить явный список bad-pattern сигналов (расплывчатые метрики, flexible stopping, session mismatch) для надёжного срабатывания restraint.
Ключевой вывод

Тестирование подтвердило типологию скилов: ценность появляется там, где скил кодирует конкретную формулу (расчётный), переопределяет дефолтное поведение (restraint), или структурирует reasoning при слабом контексте (концептуальный). Три структурных скила показали нулевую дельту изолированно — это ожидаемо и не означает, что они не нужны. Главная задача следующего этапа — chain-тест, который покажет реальную ценность полного suite.
