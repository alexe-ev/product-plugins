Key Findings
CONFIRMED
The skill is fully deterministic. 9/9 runs at 100%, stddev = 0. Every run — regardless of model temperature or sampling variation — produces the correct output structure. This is the primary evidence that SKILL.md captures all critical behavioral rules needed for this task type.
SYSTEMIC
Two baseline failure patterns are structural, not stochastic. (1) Baseline never splits bundled hypotheses — 0/3 in Eval 1 across all runs. This is a gap in base model training, not a random miss. (2) Baseline never labels confidence level — 0/6 across Evals 2 and 3. Without these labels, downstream skills (validate-hypothesis-quality, define-success-metrics) cannot decide whether to proceed or wait for more context.
SCOPE CREEP
Baseline has unpredictable scope. Without-skill timing: 10–100 seconds (stddev = 30.4s). One Eval 1 run produced a full experiment design with timeline, rollout plan, and sample size calculations in 100s. Two runs returned short outputs in ~10–22s. The skill contains explicit instructions not to advance to design-experiment-plan — baseline has no such guardrail.
WEAK ASSERTION
One assertion has low discriminating power. uplift_30pct.challenged passes for both configs (3/3 each in Eval 3). Flagging a 30% lift as "unrealistic" is basic model-level common sense. Suggested replacement: "discovery questions targeting product area, funnel stage, and user segment are explicitly listed" — this is specific behavior the skill enforces that baseline skips.
COST
Token overhead is justified. The skill costs ~3,160 additional tokens per invocation (+13%) to read SKILL.md. In return, it eliminates all output variance, prevents scope creep, and ensures the output is always consumable by downstream skills in the hypothesis validation pipeline. For a conceptual skill in a multi-step product workflow, this is a favorable tradeoff.
