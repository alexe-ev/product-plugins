Ключевые выводы

🧠
Baseline уже обучен на этой области
Экспериментальная аналитика — хорошо задокументированная область с устойчивым корпусом литературы. Паттерны guardrail conflict, peeking, stat vs practical significance, novelty effect — всё это «учебниковые» ошибки, которые модель знает без подсказок. Скил не добавляет нового знания.
🏗️
Ценность — в структуре, не в рассуждениях
Скил задаёт конкретный output format (6 обязательных секций) и result classification vocabulary (Positive / Positive with caution / Negative / Neutral / Inconclusive / Descriptive only). Без скила baseline даёт правильные ответы, но в произвольном формате. Скил нормализует это для downstream handoff.
🔍
Дизайн eval'ов был недостаточно слепым
Все «ловушки» были явно указаны в промпте (82k vs 45k notifications, Week 1: +17% vs Week 2: +2.3%). Baseline решал задачу чтения, а не рассуждения. Реальный тест потребовал бы скрытых сигналов или вычислений, которые нужно сделать самостоятельно.
📊
Сравнение с другими скилами
estimate-sample-size: разрыв появился через конкретный формульный баг. design-experiment-plan: разрыв через pseudo-complete ловушки. analyze-experiment-results: нет формульных багов и нет restraint-поведения которое базовая модель нарушала бы. Другой тип скила — другой тип ценности.

Рекомендации

1
Высокий
Найти кейсы где сигнал неявный и требует вычисления
Следующая итерация должна содержать кейсы, где «ловушка» не написана явно. Например: дать только сырые данные (control: 1,245 конверсий из 18,700; test: 1,389 из 19,100) без p-value — и проверить, правильно ли модель вычислит и интерпретирует результат. Или дать segment cuts с Simpson's paradox без указания на проблему.
2
Средний
Протестировать downstream handoff: соблюдение output format
Ценность скила — в стандартизации. Стоит добавить assertion, которая проверяет, что ВСЕ 6 обязательных секций присутствуют в выводе с правильной структурой. Это то, где baseline без скила может производить правильные рассуждения в произвольном формате.
3
Средний
Simpson's paradox как следующий кейс
Aggregate result positive, но при разбивке по сегментам (mobile vs desktop, new vs returning) оба сегмента показывают negative или neutral. Это реальный паттерн где даже опытные аналитики ошибаются. Baseline может его поймать, может нет — стоит проверить.
100% vs 100%
Нулевой разрыв — значимый результат, а не провал теста. analyze-experiment-results — это структурный скил: его ценность в нормализации формата вывода и result classification vocabulary для downstream handoff, а не в исправлении ошибок рассуждения. Baseline уже хорошо обучен на паттернах экспериментальной аналитики. Чтобы найти реальный разрыв, нужны кейсы с неявными сигналами (Simpson's paradox без подсказки, вычисление из сырых чисел) или строгая проверка output format — 6 секций, правильные classification labels.
