Ask the user for: feature or product area to instrument, key metrics or decisions the tracking should support. Optionally: existing tracking schema or event taxonomy, analytics tooling, engineering constraints on instrumentation.

Apply the skill at skills/plan-event-instrumentation/SKILL.md.

If required inputs are missing, list them and stop. Output: event tracking plan (event name, trigger, properties), naming convention and taxonomy, funnel events identified, identity and session tracking approach, coverage check (metrics vs. planned events), engineering implementation notes, events not covered and why.
